# AGENT.md

## Coding Guidelines

Follow these rules whenever writing, modifying, or reviewing code in this project.

### 1. Write Humanized Code

* Write code as a human developer would naturally write it.
* Keep the code readable, understandable, and maintainable.
* Use meaningful and descriptive names for variables, functions, components, and files.
* Avoid unnecessarily clever, complicated, or overly abstract solutions.
* Prefer clear code over code that is optimized only for brevity.

### 2. Keep Code Simple

* Always choose the simplest solution that correctly solves the problem.
* Avoid unnecessary dependencies, abstractions, wrappers, or helper functions.
* Do not over-engineer simple requirements.
* Reuse existing project utilities and components when appropriate.
* Follow the existing project structure and coding patterns.

### 3. Keep Code Concise

* Write only the code that is required.
* Remove unnecessary conditions, variables, comments, and duplicate logic.
* Avoid repeating the same logic when a simple reusable solution is appropriate.
* Do not generate large amounts of code when a smaller implementation can solve the problem.

### 4. Code Quality

* Code must be correct, reliable, and error-free.
* Consider edge cases before implementing a solution.
* Do not introduce unnecessary breaking changes.
* Preserve existing functionality unless the requirement explicitly asks for a change.
* Check for TypeScript, JavaScript, React, API, and runtime errors before considering the implementation complete.

### 5. Before Modifying Code

Before making changes:

1. Understand the existing implementation.
2. Identify the files and components affected.
3. Follow the existing architecture and conventions.
4. Make the smallest necessary change.

### 6. After Modifying Code

After making changes:

1. Check for syntax and type errors.
2. Check for unused imports and variables.
3. Check that existing functionality is not unintentionally broken.
4. Keep the final implementation clean and concise.
5. Do not leave temporary code, debugging statements, or unnecessary comments.

### Core Principle

> **Write simple, humanized, concise, readable, and error-free code.**

When there are multiple valid approaches, prefer the one that is easiest for another developer to understand and maintain.
